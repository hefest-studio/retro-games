# LODE RUNNER — контракты модулей

Проект: браузерный ремейк **Lode Runner** / «Погружение» в папке `lode-runner/`.
Открывается как `lode-runner/index.html` по `file://`, без сборки, CDN и интернета.
Стиль: тёмный неоновый интерфейс + два режима графики (8-бит / современный «неон»),
русский язык по умолчанию (есть EN), 8-битная оригинальная музыка на WebAudio.

Grid: **28 × 16** (28 столбцов, 16 строк, строка 0 — верх).
Ассеты: только код, никаких внешних файлов, шрифтов и картинок.

---

## 1. `js/levels.js` — данные уровней (владелец: level-architect)

Файл определяет глобальную переменную:

```js
window.LR_LEVELS = [
  { name: "Разминка", hint: "Соберите всё золото и найдите выход.", rows: [ /* 16 строк по 28 символов */ ] },
  // ... ровно 10 уровней
];
```

### Символы

| Символ | Значение |
|---|---|
| `#` | монолитная стена (не копается) |
| `=` | кирпич (копается игроком, но для прохождения **не требуется**) |
| `H` | лестница |
| `-` | канат/перекладина |
| `$` | золото (проходимая клетка) |
| `@` | старт игрока, ровно один |
| `X` | старт врага (1–3 на уровень) |
| `E` | выход, ровно один |
| `.` | пусто |

### Жёсткие требования

1. Ровно 10 уровней. У каждого есть `name` (RU, до 22 символов), `hint` (RU, до 90 символов), `rows`.
2. `rows.length === 16`, каждая строка ровно 28 символов, только символы из таблицы.
3. Ровно один `@`, ровно один `E`, 1–3 `X`, 3–8 `$` на уровень.
4. Весь уровень огорожен `#` по периметру (кроме клеток `E`/`H` в верхней части, если выход встроен в верхнюю стену — тогда допустим проём).
5. `@` и каждый `X` стоят на опоре (см. ниже) и не внутри стены.
6. **Любое золото и выход достижимы от `@` без копания кирпичей `=`** (копание — только тактика против врагов). Достижимость проверяется BFS по правилам движения ниже.
7. Уровни не должны быть пустыми/скучными: используйте лестницы, канаты, кирпичные платформы, карманы с золотом. Сложность растёт: 1 — обучение, 5 — канаты, 8–10 — лабиринты.
8. Строки — валидный UTF-8, но сама карта только из ASCII-символов.

### Правила движения для проверки достижимости (движок будет вести себя так же)

- **Проходимые клетки:** `.`, `$`, `H`, `-`, `@`, `X`, `E`. Непроходимые: `#`, `=`.
- **Опора** в клетке `(x,y)`: клетка ниже — `#`, `=`, `H` или `-`; ИЛИ сама клетка — `H` или `-`.
  Выход за нижнюю границу считается опорой только для страховки, но уровень должен иметь нижнюю стену.
- **Горизонтально:** из клетки с опорой в соседнюю проходимую. Если после шага опоры нет — персонаж падает вниз по проходимым клеткам, пока не найдёт опору; вылет за нижнюю границу = смерть.
- **Вверх по лестнице:** если текущая клетка `H`; целевая клетка проходима. (Можно забраться на верх лестницы.)
- **Вниз:** если текущая клетка `H` или клетка ниже — `H`, и целевая проходима.
- **Канат:** стоять можно в клетке `-` (и на клетке над `-`); по канату ходят только горизонтально, вертикально — нельзя.
- Враги используют те же движения, но не копают.
- Гравитация непрерывна: нельзя «остановиться» в воздухе.

### Проверка

Положить в `lode-runner/tools/validate-levels.mjs` автотест (Node.js, без зависимостей):
загрузить `js/levels.js` (можно через `vm`/чтение файла), проверить все требования и BFS,
запустить `node tools/validate-levels.mjs`, добиться `OK`, прислать вывод.
Не менять файлы вне своей зоны (`js/levels.js`, `tools/validate-levels.mjs`).

## 2. `js/audio.js` — музыка и звук (владелец: audio-smith)

Файл определяет `window.LR.audio` (сам создаёт `window.LR = window.LR || {}`).
Только WebAudio API, никаких внешних файлов. Всё синтезируется на лету.

### Обязательный API

```js
LR.audio.unlock();              // создать/resume AudioContext (вызывается на первом жесте)
LR.audio.startMusic(mode);      // mode: 'title' | 'game'; зациклено, переключение идемпотентно
LR.audio.stopMusic();           // плавно остановить, без щелчков
LR.audio.setGameTrack(index);   // 0 | 1 — выбрать один из двух игровых треков (по уровням)
LR.audio.sfx(name);             // 'gold'|'dig'|'trap'|'die'|'win'|'exit'|'click'|'step'|'life'
LR.audio.setMuted(muted);       // true/false, глушит музыку и SFX; false — resume
LR.audio.toggleMuted();         // → boolean (новое состояние)
LR.audio.getMuted();            // → boolean
LR.audio.setVolume(v);          // 0..1, общая громкость (опционально)
LR.audio.isReady();             // → boolean
```

Поведение:

- `startMusic` можно звать до `unlock()`: желаемый трек запоминается и стартует после unlock.
- Повторный `startMusic('game')` не должен создавать второй параллельный трек.
- `sfx` безопасно вызывать до unlock (тихо игнорировать).
- Никаких исключений при любых вызовах, повторных вызовах и отсутствии AudioContext.
- Громкость музыки умеренная (не перекрывает SFX), без клиппинга. Хорошо звучит в наушниках.
- Плавные fade in/out при старте/стопе/переключении.
- Планировщик нот на lookahead (setInterval/дребезг таймеров не должен ломать ритм),
  корректная очистка при stopMusic, остановка OscillatorNode после отыгрыша.
- Работает в Chrome/Safari/Firefox: `AudioContext` + fallback `webkitAudioContext`,
  префиксный `createStereoPanner` опционален.

### Музыка (оригинальная, не копировать чужие мелодии!)

- `title` — загадочный, гипнотичный чиптюн-луп (медленнее, атмосфернее).
- `game` — энергичный «прикольный» 8-битный луп ~128–140 BPM: пуншевый бас (triangle),
  две квадратные/пульсовые дорожки (лид + арпеджио), шумовые барабаны (kick/snare/hat).
- Два игровых трека (`setGameTrack(0|1)`) должны заметно отличаться (например, A-moll и E-moll,
  разный грув), чтобы уровни звучали свежо. Треки зациклены без пауз.
- Композиции должны быть складными: 8–16 тактов, развитие, без случайных нот.
- Не использовать мелодии из оригинального Lode Runner или других игр.

### Проверка

`node --check js/audio.js`. Дополнительно можно сделать офлайн-тест планировщика без WebAudio
(заглушка AudioContext), если получится. Не менять файлы вне своей зоны (`js/audio.js`).
