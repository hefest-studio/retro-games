# МАЯЧНИЦА · пилот рисованного приключения без слов (point-and-click)

Пилот студии **«Гефест»**, папка `kvest/`. Сейчас он скрыт: его нет в каталоге и в sitemap, на странице стоит `noindex`.
Оформление — **«бумага»**, аппликация из вырезанной цветной бумаги (`js/themes/paper.js`, выбор владельца 14.11).
Серый макет (`js/themes/grey.js`) остался как отладочная тема: `index.html?theme=grey`. Обе темы работают по контракту
«КВЕСТ» (раздел «Как подключить новую тему» ниже) и регистрируются в `KVEST.themes`. Всё сделано на чистом HTML5/Canvas, оболочка —
Гефест Arcade v2.2 (меню, пауза, язык, звук, музыка), без сборки и без внешних ресурсов.

**Сюжет (без единого слова).** Посёлок фонарщиков на мысу. В шторм погас маяк, наползает туман, и рыбацкие лодки
не могут найти дорогу домой. Старый мастер слёг с простудой и рассказывает об этом мыслями-пиктограммами.
Его подмастерье Тая (коса, длинное пальто, шарф, сумка через плечо) должна собрать для большого фонаря **линзу, фитиль,
масло и огонь** и зажечь маяк. В финале лодки выходят из тумана.

## Механика
- Клик или тап — героиня идёт по полосе ходьбы. Действовать можно только с тем, до чего она дотянулась: к зоне она
  подходит сама, тянется (поза reach), и только после этого срабатывает действие. Высокое без табурета не достать.
- Курсор меняется над зонами (`use / take / go / look`, на пустом месте — `walk`). Долгий тап или правая кнопка —
  осмотр (мысль с пиктограммами).
- Инвентарь — полоса внизу. Предмет можно перетащить на объект или на другой предмет (комбинация), а можно тапнуть
  по нему и затем по цели.
- **Подсказка** (лампочка, H) — мысль-пузырь с намёком на текущую цель. Цель берётся из реестра головоломок.
  В каждой сцене одна подсказка бесплатна, дальше — по таймеру (45 с) или после мини-игры «поймай трёх светлячков».
- **Прохождение-набросок** (книжка, B, или пункт меню паузы) — карточки-шаги без слов, 5 страниц.
- Кат-сцены идут движком: мысли мастера, жесты, проход героини, финал. Тап пропускает кат-сцену.
- Прогресс сохраняется в localStorage по главам (`arcade.save.kvest.<глава>`, версия 1; см. «Спринт 1»). В меню: Новая игра /
  Продолжить · N/26 / Язык / Звук (в полной версии, когда открыто больше одной главы, — ещё «Глава N · …»). Звуковые эффекты — WebAudio, музыка — тихий эмбиент `Arcade.tracks.kvest`.
- Клавиша D включает отладку макета: подписи объектов, рамки зон, полосу ходьбы.
- **Геймпад** (движок v2.9, `js/main.js`, раздел «геймпад»): левый стик — курсор (разгон при удержании, правый стик — точно), D-pad — прыжок
  курсора к соседней цели, A — клик (удерживать на предмете из сумки — перетащить, на месте — осмотр), B — отмена / курсор к сумке и обратно,
  X — подсказка, Y — осмотр, LB/RB — герой (главы с помощниками) или предмет, LT/RT — предмет, L3/R3 — умение, Select — набросок,
  Start — пауза. Меню, пауза, «Главы», финал — навигация движка. При геймпаде подсказки внизу и на экране — значками кнопок.

## Сцены и головоломки (9 сцен, 26 головоломок)
| Сцена | Головоломки | Тип |
|---|---|---|
| 1. Мастерская | табурет под полку → маслёнка; 4 взаимозависимых тумблера → ящик (фитиль, огниво); поленья + огниво → печь; фонарь к огню | механика ×2, предметные ×2 |
| 2. Площадь | ведро → колодец; вода → пекарше (хлеб); хлеб → козе (поленница) | предметные ×3 (+ подсказка-мелодия: птицы на столбиках) |
| 3. Причал | кран: три рычага по порядку → ведро; сеть + «кошка» → рыба; рыба → кошке (ключ); ключ → сарай | механика, предметные ×3 |
| (инвентарь) | верёвка + крюк → «кошка»; мутная линза + тряпица → линза | комбинирование ×2 |
| 4. Лодочный сарай | 3 вентиля и манометр; **мини-игра «трубы»**; маслёнка → носик | механика, мини-игра, предметная |
| 5. Грот | огонь в темноте; «кошка» → ракушка из лужи; **плиты со знаками** (порядок — на табличке в сарае); ракушка → чайке (линза) | предметные ×3, наблюдательная |
| 6. Тропа на мыс | ворот + стопор + 3 оборота лебёдки → мост | механика |
| 7. Подножие маяка | **кодовые диски** (код — на чертеже в мастерской) | наблюдательная |
| 8. Лестница маяка | **мини-игра «колокольчики»**: мелодия = высоты птиц на площади | мини-игра (наблюдательная) |
| 9. Фонарная | **мини-игра «сдвижная оправа» 3×3**; линза, фитиль, масло в фонарь; огонь → маяк | мини-игра, предметные ×2 |

Итого 16 предметных, 5 механических, 3 мини-игры, 2 наблюдательные (у мелодии подсказка тоже в другой сцене).
Число головоломок считается по данным (`KVEST.PUZZLES.puzzles`).

## Как подключить новую тему («бумага» / «тушь»)
1. Скопировать `_proto/style-<имя>/theme.js` в `kvest/js/themes/<имя>.js`. Файл должен объявлять `window.KvestTheme`
   (id, name, 7 методов).
2. В `kvest/index.html` заменить строку `<script src="./js/themes/grey.js">` на новый файл. Порядок скриптов
   не менять: тема грузится после `theme-api.js` и до `main.js`.
3. Открыть `kvest/index.html?check`: в консоли должно появиться `KvestTheme <id>: OK` (это `validateTheme` с настоящей
   канвой). Затем пройти сцены в режиме отладки (D).
4. **Научить тему состояниям пилота** — без этого головоломки читаются плохо. Список — в `theme-api.js`
   (`KINDS`/`EXT_KINDS`). Главное:
   - `npc.state.type`: master, baker, goat, cat, gull, bird (+ `post`, `sing`);
   - `machine.state.variant`: stove, well, crane (`prog`, `load`), tank, gauge (`gauge`, `mark`, `ok`), spout (`drip`), winch, carriage;
   - `box.state.variant`: stool, bench (`open`, `empty`), logs, net, panel; `box.state.icon` — диски кода; `box.state.pic/part/n` — плитки оправы;
   - `pipe.state.shape/rot/wet/fixed` — плитки мини-игры; `lamp.state.big/lens/wick/oil/lit`, `lamp.state.small`;
   - `rock.state.plate/icon/down`, `rock.state.variant: steps (up) | pillar`; `bridge.state.lift`; `door.state.lock/hatch`;
   - расширенные kind: `sign` (`icons`), `shelf`, `chime` (`note`, `n`, `ring`);
   - пиктограммы — все id из `ICONS`, включая `n0…n4`, `dot1…dot3`, `lever_on/off`, `lamp_off`.
   Прототипы (`_proto/style-*`) поля из п. 4 игнорируют (все `npc` у них — одинаковые фигуры). Тема пилота
   `js/themes/paper.js` (на базе прототипа «бумага») читает их все — прототип оставлен как есть, для сравнения стилей.
5. Прогнать `node kvest/tests/engine.test.mjs`. В список `FILES` теста можно добавить новую тему, чтобы её проверял
   и Node; для текстур на пикселях `mockCtx` умеет `createImageData`/`getImageData`/`createPattern`, но `Path2D` и
   `DOMMatrix` в Node нет, поэтому такие темы проверяются в браузере через `?check`.

## Тема «бумага»: как читаются головоломки
- Интерактивное — «наклейка»: светлый бумажный контур и тень-подложка; под курсором — тёплый пульсирующий ореол.
  Предметы, которые можно взять, ещё и поблёскивают. Выходы без двери помечены флажком-стрелкой с пиктограммой сцены.
- Пустые гнёзда (дрова в печи, маслёнка под носиком, рукоять лебёдки, линза/фитиль/масло в большом фонаре) — пунктирный
  круг с бледным силуэтом нужного предмета.
- Цвет-метки: нота = цвет + высота + число точек (птицы на площади ↔ колокольчики маяка; выше нота — выше столбик и
  короче трубка); рычаги крана окрашены как части крана (`state.tint`), красный — всегда стопор/замок; у вентилей —
  точки-веса (`state.pips`); на манометре зелёная метка — цель.
- Настроения сцен — по `scene.id` (затем по `mood`): тёплая мастерская, пасмурная площадь, ветреный серо-синий причал,
  сырой сарай, грот (темнота и круг света фонаря), сумерки тропы, ночь у маяка, каменная лестница, фонарная (туман над
  морем; когда фонарь зажжён — туман расходится, тёплый свет, лодки с огоньками).
- Производительность: фактура, статичные слои (подряд идущие неподвижные элементы склеиваются в один холст), спрайты
  объектов по состоянию, ореолы и пиктограммы кэшируются (LRU, ≈20 млн пикселей); кэш прогревается в паузах браузера.
  Тени вырезок — три смещённых слоя (без `filter: blur`, это в 10 раз быстрее при сборке). В кадре — `drawImage` и живые
  детали: огонь, свет, волны, туман, персонажи «стоп-моушн» 12 к/с. Цель — 60 к/с.
- В Node (без DOM) тема рисует напрямую в контекст без кэша — так её проверяет `validateTheme` в тестах;
  `KVEST_STRICT = true` отключает «мягкое» падение отрисовки (ошибка не прячется за нейтральным прямоугольником).

## Подсказки и набросок — тушью (`js/themes/ink-sketch.js`)
Игра в «бумаге», а то, что объясняет, — эскизом тушью: мастер рисует мысли пером (в кат-сценах штрих проявляется, перо
ведёт линию), подсказка-лампочка — карточка слоновой кости с эскизом цели, прохождение — блокнот героини (разворот, шаг
на страницу, открыты только пройденные и текущий; листать стрелками или свайпом). Эскиз цели — данные `puzzles[].ink`
(глифы из настоящих объектов сцен, цель — петля киноварью, порядок — засечки). Глиф делается из того же спрайта paper,
что и в сцене (контур по альфе, линии — оператор Собеля, тон — штриховка), поэтому силуэт узнаётся. Модуль вешает на тему
хуки `drawHint`, `drawWalkbook`, `drawThought(opts.style:'ink')` (описаны в `theme-api.js` и `THEME-CONTRACT.md`).
«Анимация штриха» (меню и пауза, `localStorage['arcade.kvest.inkAnim']`): вкл — спокойное «кипение» 2,5 раза в секунду
и анимация пера; выкл — всё статично.

## Спринт 0: «как релиз» и демо
- **HiDPI.** Канва рисует в физическом разрешении: логика 960×540, физический размер = размер на экране × `devicePixelRatio`,
  с потолком по памяти. Кэши темы «бумага» (спрайты, ореолы, кадры персонажей, фактура, пиктограммы) и эскизы тушью строятся
  в том же масштабе (`theme.setResolution(s)`), поэтому блиты идут 1:1. Потолок масштаба и бюджет кэша — по классу устройства
  (`main.js`): телефон ≤ 1,5 и ≈ 29 МБ; планшет и обычный десктоп ≤ 2 и ≈ 50 МБ; десктоп с ретиной/4K ≤ 3 и ≈ 110 МБ; память ≤ 2 ГБ — ≤ 1,25.
  Кадры персонажей кэшируются по кадру «стоп-моушн» (12 к/с), тон сцены запечён в виньетку, лишняя заливка фона не рисуется.
- **Адаптивное качество** (`?nogov` — выключить, `?tier=N` — задать): ступень 0 — полное разрешение; 1 — без виньетки, туман
  в две полосы; 2 — масштаб 1; 3 — масштаб «как на экране». Ниже 38 к/с — ступень вниз, стабильно 58+ — вверх; ступень запоминается.
- **Устройства.** Канва занимает весь экран с учётом вырезов (`safe-area`), кнопки «Каталог / Пауза / Во весь экран» — в полях
  сбоку или над канвой. Телефон в портрете — экран «Поверните устройство» с иллюстрацией в стиле игры (сцены — широкие композиции
  16:9, в портрете они стали бы втрое меньше, а инвентарь снизу не возвращает размер сцены); планшет в портрете играет в полосе.
  Тач: тап — действие, долгий тап — осмотр (кольцо вокруг пальца), перетаскивание предмета — он приподнят над пальцем, захват —
  по всей высоте полосы; на маленьких экранах промах рядом с зоной засчитывается ближайшей зоне. Масштаб и прокрутка страницы
  отключены. F или кнопка — полноэкранный режим (на Android ещё и фиксирует ландшафт).
- **Демо / полная** (`js/edition.js`): `KVEST_EDITION = 'demo' | 'full'`, параметры `?demo`, `?edition=full|demo`. Демо после
  финала показывает «Продолжение — в полной версии» с кнопками «Вернуться в меню» и «Узнать больше» (`KVEST_MORE_URL`, пока — каталог;
  одно действие — переход в той же вкладке, `Edition.goMore`); полная — «Глава N+1» (если она есть в сборке) или «Глава N+1 — скоро».
- **Хуки настольной обёртки** (приватное издание `arcade-full/steam`, Electron): `js/main.js` читает необязательные поля `K.Edition` —
  `storage` (сохранения глав вместо localStorage), `quit` (пункт «Выход» в главном меню и паузе, строка `quit`), `fullscreen` (F, кнопка и
  пункт «Во весь экран» переключают окно приложения), `langs` (языки для выбора по умолчанию), `release` (без отладки D/E и статистики плейтеста).
  В публичном издании этих полей нет — поведение прежнее.
- **EN-оболочка** (`js/i18n.js`): все строки меню, паузы, настроек, финала, поворота, кнопок страницы; язык — сохранённый выбор
  или язык системы, переключатель «Язык» / L. Рабочее EN-название — константа `TITLE_EN` (пока транслит).
- **Статистика плейтеста** (`js/stats.js`): время в каждой сцене и заходы, подсказки (бесплатные / по таймеру / после светлячков),
  ошибки (предмет не туда, комбинация, неверный ход механизма или ноты), осмотры, головоломки с отметкой времени. Только локально
  (`localStorage['arcade.kvest.stats']`), ничего не отправляется. Видно в отладке (D), выгрузка — E в отладке, пункт паузы
  «Статистика плейтеста → файл» (с `?playtest` или при включённой отладке) и кнопка на финальном экране.

### Плейтест владельца
1. Открыть `kvest/index.html?playtest` (демо) — на компьютере, телефоне или планшете.
2. Играть как обычно. D — панель статистики поверх игры.
3. После финала нажать «Статистика плейтеста → файл» (или в любой момент: пауза → тот же пункт). Сохранится
   `kvest-playtest-ГГГГММДД-ЧЧММ.json` — его и прислать. «Продолжить» в меню продолжает ту же статистику, «Новая игра» начинает новую.

## Спринт 1: движок глав (публичный код; контент глав 2+ — только в приватной полной сборке)
- **Реестр глав** (`js/chapters/index.js`, как реестр миссий ПРИИСКа). Глава = файл данных `{ id, n, title, scenes, puzzles, map?, music?, win? }`,
  регистрируется `KVEST.Chapters.register()`. Глава 1 — `scenes.js` + `puzzles.js`. Списки изданий: `demo: ['ch1']`, `full: [...]` — в публичном
  файле только id; файлы глав 2+ кладёт поверх публичной игры приватный репозиторий при сборке и грузятся они только с флагом `full`.
  Нет файла — главы нет в меню, игра не ломается. Активная глава подставляется в `KVEST.SCENES/PUZZLES` (их читают тема и эскизы тушью).
- **Выбор главы и сохранения по главам.** Пункт меню «Глава N · название» — когда в сборке открыто больше одной главы (следующая
  открывается после прохождения предыдущей; `?chapter=N` — выбрать и открыть сразу, для плейтеста). Сохранение — `arcade.save.kvest.<id>`
  (запись помнит главу и не грузится в чужую), пройденные главы и выбор — `arcade.kvest.chapters`. **Миграция:** старое сохранение пилота
  `arcade.save.kvest` при старте переносится в `arcade.save.kvest.ch1` и удаляется (более новое сохранение главы 1 не затирается).
  У главы может быть своя музыка (`music` — трек секвенсора движка).
- **Карта побережья** (`chapter.map`) — экран-переход между местами главы: узлы-места открываются условиями (`need`), тропы — когда открыты
  оба конца; кликабельны места, связанные открытыми тропами со стартом; фишка героини идёт по тропе, потом вход в сцену. Карта — обычная
  сцена движка (выход `to: <id карты>`), тема рисует kind `mapsheet`, `trail`, `mapnode` (`state.lit` — огонь места зажжён), `maptoken`.
- **Сцена с двумя состояниями** (`scene.phase = { flag, a, b }`): у элементов слоёв, объектов и зон — `phase: 'имя'`, своя полоса ходьбы
  `walkPhase`. Переключение — любым действием над флагом (рычаг, кат-сцена) или **таймером главы** (`puzzles.timers = [{ flag, every, where }]` —
  флаг меняется сам, пока героиня в сценах `where`). Уровень воды анимируется (`scene.phaseMix` 0..1, kind `tide`); если полоса ходьбы стала
  короче, героиня отходит. Поиск по состояниям считает таймер переходом «подождать» и проверяет, что прилив не запирает героиню (`positionSafe`).
- **Новый механизм `gears`** — сцепленные шестерни (клик крутит шестерню вперёд, сцепленные — назад). Мини-игра «трубы» принимает свои
  источник и приёмник (`srcObj`, `dstItems`).
- **Новые kind и состояния** — в `theme-api.js` и `THEME-CONTRACT.md` (расширение 15.11); нарисованы в `paper` и `grey`, эскизы тушью строятся
  из спрайтов paper автоматически.

## Спринт 2: движок помощников (публичный код; глава 3 с помощниками — только в приватной полной сборке)
- **Герои.** Тая есть всегда; глава объявляет помощников: `puzzles.heroes = [{ id: 'dog' | 'gull', need }]` (пёс Вьюн, чайка Кира).
  Активный герой — `st.hero`; переключение — **портреты над сценой** (`LAYOUT.heroes`, тап/клик), Tab — следующий, 1/2/3 — по номеру.
  Свободные герои ходят отрядом (идут следом за активным); у края полосы ходьбы — встают впереди.
- **Сцена может не пускать помощника:** `scene.heroes = ['taya', 'dog']` — портрет чайки погашен, в выход она не идёт (мысль «не пустят»).
- **Глаголы.** Правило с полем `hero: 'dog' | ['dog', 'gull']` срабатывает у этого героя; правило без `hero` — только у Таи (главы 1–2 не
  меняются). Механизмы крутит Тая. Позы пса: dig, sniff, pull, hold, bark…; чайка взлетает к зоне (и вбок — над водой, к уступу) и роняет/несёт.
- **Удержания** — «X держит, пока Y действует»: `puzzles.holds = [{ id, scene, hs, by, need, until, pose }]`. Герой из `by` жмёт зону — и держит
  (флаги `held:<id>`, `by:<id>:<герой>`), управление само переходит к Тае; держащий остаётся в своей сцене (можно держать в одной сцене, а действовать
  в другой). Отпустить — сделать его активным и шагнуть/нажать ту же зону; `until` — отпускает сам, когда дело сделано. Удержание может менять сцену
  (флаг `held:…` в `bind` объектов или как флаг фазы сцены).
- **Умения** (тап по портрету активного помощника или Q): пёс — **нюх**: след лапами **тушью** к спрятанному (зоны `scent: true`, где у пса есть дело);
  чайка — **взгляд сверху**: сцена под калькой, тушью обведено, где и кто из героев может действовать (и куда идти дальше).
- **Таймер главы с условием** (`timers[].need`) — например, ветер перестаёт меняться, когда дело сделано. `bind` объекта принимает список (условие «и»).
- **Поиск по состояниям и бот** учитывают героев: состояние = флаги + инвентарь + удержания (положение свободных героев = сцена активного);
  переходы «держать» и «отпустить», выход проходим, если его может пройти хоть один свободный герой. Бот переключает героев тапом по портрету.
- **Темы:** `drawHelper` (пёс и чайка во всех позах), портреты в `drawUI`, `drawActiveMark` (флажок над активным героем), `drawTrail` / `drawOverview`
  (тушью в «бумаге» — `ink-sketch.js`, в сером макете — упрощённо); новые kind — в `theme-api.js` и `THEME-CONTRACT.md` (расширение 15.11, спринт 2).
- **Звук:** события `switch`, `sniff`, `dig`, `pull`, `release`, `flap`, `mill`, `terns`, `chirp` (+ `bark`, `gull`).

## Спринт 3: подводные механики (публичный код; глава 4 с ними — только в приватной полной сборке)
- **Мягкий таймер воздуха** (`js/water.js`). Глава объявляет `puzzles.air = { max: секунды, speed: px/с под водой, home: { scene, x } }`,
  подводная сцена — `scene.water = { pockets, murk, vis, sounds }`. Под водой запас убывает: в пути — секунда за секунду, стоя — вдесятеро
  медленнее (таймер ограничивает путь, а не раздумья); в кат-сцене, мини-игре и блокноте не убывает. В **воздушном кармане**
  (`pockets: [{ id, x, w, need }]` — колокол-водолаз, родник пузырей, воздух под сводом) пополняется за секунду. Кончился — **не смерть, а
  мягкий возврат**: лист темнеет, героиня у последнего кармана (кармана больше нет — в `home` главы); флаги, предметы и головоломки не
  меняются. С суши под воду — всегда с полным запасом. Индикатор — **шкала пузырьков без цифр** (`LAYOUT.air`; мало воздуха — янтарная,
  пульсирует) и шлем-пузырь героини. Воздух и последний карман пишутся в сохранение.
- **Мутная вода и звук как подсказка.** `scene.water.murk` (`true` или условия) — видно только круг `vis` вокруг героини, остальное закрыто
  бледным облаком ила. `scene.water.sounds = [{ id, x, y, note 0..4, need, every, phase, big, harsh }]` — колокола-ориентиры: звенят сами раз
  в `every` секунд и все по очереди слева направо — по умению Таи **«прислушаться»** (Q или тап по её портрету; под водой портрет Таи
  с ухом есть и в главах без помощников). Событие движка `ring`: **панорама** — где колокол (лево/право от героини), **высота тона** — какой
  (нота из пяти нот «песни маяка»; строй не меняется), расстояние — громкость и «глухота» (срез фильтра); `audio.js` играет его через
  WebAudio (`StereoPanner` + ФНЧ), без него — простым тоном. **Звук всегда продублирован визуально**: кольца-волны тушью от источника с
  карточкой-нотой (точки, как у колокольчиков главы 1; ближе — жирнее; `harsh` — ломаное красное кольцо, лязг железа) — играть можно без звука.
  Зона с полем `guide: 'id источника'` в мути активна, только пока её колокол звенит (нашли по звону, а не перебором пикселей); активные
  карманы воздуха видны сквозь муть столбиком пузырей. Курсор над зоной, которая дальше круга видимости, остаётся «идти» —
  мышью невидимое не нащупать.
- **Помощники выборочно.** Под воду (`scene.water`) идут только герои с `dive: true` в объявлении главы — то есть обычно одна Тая; ещё
  `heroes: [{ id, not: [сцены] }]` / `only: [сцены]` и прежний `scene.heroes`. Портреты тех, кого сцена не пускает, погашены (значок воды).
  Помощники работают сверху: удержание на берегу действует и на подводные сцены (Вьюн держит лебёдку — колокол-водолаз стоит на дне, это
  условие кармана воздуха и выхода), чайка действует над водой (роняет буёк — под водой зазвучал новый колокол).
- **Поиск по состояниям и бот.** Воздух в состояние **не входит** (перебор не растёт): это ограничение длины пути между карманами.
  `KVEST.Water.reach` считает, с каким запасом воздуха героиня входит в подводные сцены (карман даёт полный запас), зона доступна, только если
  до неё хватает воздуха (`hsOk`); поиск считает с запасом (85 % настоящего воздуха). `positionSafe`: из каждого достижимого кармана можно
  вернуться к старту. Бот перед каждым действием под водой считает путь «туда и обратно к карману», при нужде заходит в карманы
  (счётчик `refills`), после мягкого возврата повторяет действие (`outs` — сколько раз воздух всё же кончился).
- **Темы:** хук `drawWater(ctx, model.water, t)` (`paper-water.js`, упрощённо — в `grey.js`); новые kind `divebell`, `seabell`, `kelp`,
  `airpocket`, `buoy`, `arch`, `crane`, `ruin`, `whale`, палитры `baypier`, `seabed`, `murk`, `deep`, `foundry`; эскизы тушью для новых
  объектов строятся из тех же спрайтов автоматически. Мини-игра «мелодия» принимает `kind: 'seabell'` (колокола вместо трубок), крупный
  план — свою палитру интерьера (`pal`).
- **Звук:** события `ring` (нота, панорама, глухота), `air`, `airlow`, `surface`, `bubbles`, `dive`, `clangiron`, `whale`.

## Спринт 4: сны, живая тушь, хор огней, финал (публичный код; главы 5–6 — только в приватной полной сборке)
- **Сцены-сны** (`js/dream.js`). `KVEST.Dream.variant(base, spec)` строит на лету вариант уже существующей сцены «наоборот»: зеркало
  (`mirror` — объекты, зоны, полоса ходьбы, точка входа), свои выходы (`exits`; выходы основы, которым не дали назначения, убираются),
  `keep`/`drop`, перевёрнутые условия (`invert` — то, что открывало, закрывает; булевы поля `state`), свои объекты, зоны и слои, ночь
  и палитра сна (`mood`, `pal`). Данные основы не меняются и никуда не копируются — глава хранит только описание отличий. **Два
  состояния** — тем же механизмом, что прилив (`scene.phase`): `wake: 'флаг'` — сон (флаг снят) / явь (поднят), `only: { dream, wake }`
  и `onlyHs` — что есть только в одном состоянии, `palWake` — палитра яви (`scene.palPhase` работает и у обычных сцен: ночь → рассвет).
  Модель: `scene.dream = { of, mirror, up, wake, mix }` — тема рисует «вуаль сна» хуком `drawDream` (в яви тает).
- **Живая тушь.** `puzzles.inks = [{ id, scene, hs, item, obj, need, hero, keep, do, puzzle }]`: эскиз-предмет (`ink_door`, `ink_bridge`,
  `ink_ladder`, `ink_boat`, `ink_lamp`) применяют к пустому месту (kind `inkspot`) — перо рисует объект (kind `inkdraw`, `state.drawn` 0..1
  за 1,5 с), он оживает: флаг `ink:<id>`. Дальше — обычными средствами движка (дверь — выход с `need`, мост — `walkIf`). `prepare` один раз
  превращает тушь в правила — их видят игра, поиск и бот (бот перетаскивает эскиз на место).
- **Межсценовая головоломка — хор огней** (`js/chorus.js`). `puzzles.chorus = [{ id, target: [ноты], voices: [{ id, scene, hs, note, need,
  node }], onMiss, onSolve, puzzle, show }]`: голоса в разных сценах поют ноты по порядку `target`; спетое сохраняется (флаги
  `ch:<id>:<k>`, `lit:<id>:<голос>`), ошибка не тупик — огни мягко гаснут, начинай заново. Модель `model.chorus` — строка мелодии
  (хук `drawChorus`, `LAYOUT.chorus`, без цифр); на карте узлы-голоса несут ноту и номер, между спетыми подряд — нить мелодии (kind
  `songline`); узел карты без `scene` — дальний огонь (виден, не зона).
- **Финальная кат-сцена движком:** шаги `['move', объект, dx, dy, сек]` (объект плывёт — тема сдвигает готовый спрайт),
  `['fx', 'dawn' | 'fogclear' | 'songrings' | 'white', сек]` (эффект на весь лист, хук `drawFx`), `['notes', [ноты], шаг, голос]` (мотив по
  нотам: событие `note`; поют и звенят объекты с той же нотой — птицы, колокола), `['go', сцена, x]`. Пропуск тапом доводит всё до конца.
- **Титры и выбор главы.** После финала последней главы полной версии — титры (строки — только из словаря i18n RU/EN: название, студия,
  «музыка: процедурная»; трек — `chapter.creditsMusic`), затем экран «Конец» (`edition.js`: `kind: 'end'`, пункты «Вернуться в меню»,
  «Титры»). Пункт «Глава» открывает экран **«Главы»**: все главы игры по порядку, открытые и закрытые, прогресс каждой (по сохранению) и
  общий процент (`KVEST.Chapters.summary`); в демо главы полной версии показаны без названий.
- **Темы:** хуки `drawDream`, `drawChorus`, `drawFx`; kind `inkdraw`, `inkspot`, `inkthought`, `upfall`, `clang`, `songline`, `fogbank`;
  палитры сна у «бумаги» (`dream_<палитра>`); `paper-dream.js`, упрощённо — в `grey.js`. Контракт — `THEME-CONTRACT.md` (расширение 19.11, спринт 4).
- **Звук:** события `pen`, `hush`, `wake`, `voice` (голос огня — нота из тех же пяти; «мимо» — мягко), `note` (мотив; голос Кита — октавой ниже), `dawn`.
