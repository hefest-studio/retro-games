# CONTRA: НЕОНОВЫЙ РАССВЕТ — аудиосистема

Техническая и музыкальная справка по `src/audio.js` (оригинальный чиптюн-движок
на WebAudio). Никаких сэмплов, файлов, CDN и сети: вся музыка и все эффекты
синтезируются на лету. Скрипт классический (IIFE), единственный глобальный
объект — `window.CONTRA_AUDIO`.

---

## 1. Публичный API

```js
window.CONTRA_AUDIO = {
  unlock(),                    // создать/resume AudioContext; можно звать на каждый жест
  isReady(),                   // true, если контекст существует и state === 'running'
  startMusic(name),            // 'title' | 'stage1' | 'stage2' | 'boss' | 'victory' | 'gameover'
  stopMusic(fadeSec),          // по умолчанию 0.25 c; идемпотентно
  sfx(name),                   // fire-and-forget; до unlock молчит; не бросает
  setMuted(bool), toggleMuted(), getMuted(),
  setVolume(0..1), getVolume()
};
```

Гарантии:

* **Ни один метод не бросает исключений** — ни до `unlock()`, ни с мусорными
  аргументами (`startMusic(42)`, `sfx(null)`, `setVolume('abc')` игнорируются).
* `unlock()` можно звать сколько угодно раз — контекст создаётся один раз.
* `startMusic(name)` до `unlock()` запоминает трек и запускает его автоматически
  после разблокировки. Повторный вызов с тем же треком идемпотентен: второй
  планировщик/второй трек не создаётся.
* `sfx()` до `unlock()` — тихий no-op (без очереди и без создания узлов).
* `stopMusic()` во время фейда и вызов до `unlock()` безопасны.
* `setMuted(true)` запоминает текущий трек и позицию; `setMuted(false)` продолжает
  его с того же шага. Если трек ещё не играл — стартует по `unlock()`.
* Громкость клампится в `[0, 1]`, нечисловые значения игнорируются.
* Мьют/громкость не сохраняются между перезагрузками страницы (осознанно:
  `file://` + приватный режим не дают надёжного `localStorage`).
* При скрытии вкладки (`visibilitychange`) планировщик останавливается, контекст
  уходит в `suspend()`. При возврате — `resume()`, позиции нот пересчитываются от
  `currentTime`, пачки «догоняющих» нот не возникает.

### Интеграция в игру

```js
// на первом пользовательском жесте:
CONTRA_AUDIO.unlock();

// можно и до жеста — движок сам запустит после unlock:
CONTRA_AUDIO.startMusic('stage1');

// события игры:
CONTRA_AUDIO.sfx('shot_spread');
CONTRA_AUDIO.sfx('explode');
CONTRA_AUDIO.startMusic('boss');      // кроссфейд ~0.22 c
CONTRA_AUDIO.stopMusic(0.4);
CONTRA_AUDIO.setMuted(true);
```

Движок сам вешает одноразовые `pointerdown`/`keydown`/`touchstart`-слушатели,
поэтому даже если игра забудет позвать `unlock()`, первый клик/клавиша запустит
звук (позже слушатели снимаются).

## 2. Граф WebAudio

```
 lead (PeriodicWave 25%/12.5%) ──┐
 arp  (PeriodicWave 12.5%) ──────┼─► channel gains ─► track gain ─┐
 bass (triangle) ────────────────┤        lead ─► echo send ─► delay ─► LP ─┐
 drums (noise + triangle) ───────┘                               feedback ◄─┘
                                                                         │
                                      musicBus (0.5) ◄────────────────────┘
                                                                         │
 SFX (osc/noise, 16 видов) ──────────────────────► sfxBus (0.75) ────────┤
                                                                         ▼
                                             master gain (0.8) ─► compressor ─► tanh-limiter ─► destination
```

* **Master 0.8**, **music 0.5**, **sfx 0.75** — значения по умолчанию; `setVolume()`
  меняет только мастер-гейн, `setMuted()` плавно уводит его в 0.
* Компрессор: threshold −14 dB, knee 10, ratio 8, attack 4 мс, release 220 мс.
* После компрессора — `WaveShaper` с кривой `tanh(1.6x)/tanh(1.6)` (мягкий
  лимитер, пик ≤ 1). Замеры в Chrome: пик треков 0.50–0.74, при `setVolume(1)` —
  0.80, клиппинга нет.
* Эхо — короткий delay (3 шестнадцатых текущего темпа, 90–850 мс), feedback ≤ 0.55,
  lowpass 2.6 кГц; только для лида, глубина задаётся в партитуре.
* Крупные SFX (`explode`, `death`, `alarm`) слегка присаживают шину музыки
  (ducking до −3.5 дБ на 0.16–0.28 c), чтобы эффекты не тонули в миксе.

## 3. Синтез

* **Импульсные волны** — `PeriodicWave` из ряда Фурье для скважности 12.5% и 25%
  (33 гармоники, встроенная нормализация). Если `createPeriodicWave` недоступен,
  используется `OscillatorNode.type = 'square'`.
* **Бас** — нативный треугольник, огибающая attack 8 мс, спад к сустейну.
* **Барабаны** — один общий буфер белого шума 2 с (создаётся один раз на контекст):
  kick = треугольник с падением 145→44 Гц + шумовой клик; snare = bandpass-шум +
  треугольный корпус; hat = highpass-шум (закрытый/открытый); tom = треугольник
  210→105 Гц + шум; crash = длинный highpass-шум.
* **SFX** — 1–3 узла на эффект, экспоненциальные огибающие, небольшой рандом
  высоты/панорамы, чтобы серия выстрелов не звучала механически. Все SFX короче
  0.5 c (кроме `alarm` ≈ 0.62 c).
* **Чистка** — у каждого одноразового источника `onended` отключает всю цепочку;
  при смене/остановке трека отключаются его шины, эхо и delay-feedback.

## 4. Планировщик

* Lookahead **0.12 c**, тик **25 мс**, ноты ставятся по `ctx.currentTime`, а не по
  `setTimeout`.
* Все треки компилируются при загрузке скрипта в `byStep[]` (шаг = 16-я нота),
  поэтому тик — это только обход готовых событий.
* Лупы бесшовные: шаг заворачивается с `step = 0`, время продолжает накапливаться
  (нет паузы/пересчёта на границе). Проверено в Chrome на границе лупа `boss`
  (17.1 c): 20 окон по 250 мс — RMS 0.17–0.24, провалов и NaN нет.
* Одноразовые `victory`/`gameover` играют ровно один проход, затем плавно
  затухают за 1.15 c и сами освобождают узлы; `desired` сбрасывается.
* Смена трека — кроссфейд 0.22 c (старый gain → 0, новый 0 → 1), `stopMusic` —
  фейд по умолчанию 0.25 c. По завершении фейда интервал планировщика очищается;
  «убежавших» таймеров нет (проверяется smoke-тестом).
* Защита от залпа: если `nextTime` отстал от `currentTime` больше чем на 0.2 c
  (сон/зависание), он переустанавливается, а не догоняет пачкой нот.

## 5. Партитура

Каждый трек — это BPM, массив аккордов по тактам, строка лида, паттерн
арпеджио (8–16 шагов), паттерн баса (`R` корень, `3/5/7`, `O` +октава,
`L` −октава, `b` −полутон), шумовые дорожки и fill-такты. Данные лежат в
`SONG_DEFS`; компилятор проверяет длины (предупреждения в консоль), поэтому
smoke-тест падает при ошибке в партитуре.

| Трек | Тональность | BPM | Такты | Длительность | Форма / гармония | Настроение |
|---|---|---|---|---|---|---|
| `title` | A minor | 104 | 12 | ≈27.7 c, луп | Am F C G / Am F Dm E / Am F G Am | тёмный неон, 1988 meets 20XX |
| `stage1` | A natural minor | 150 | 16 | ≈25.6 c, луп | Am Am F G / Am C F G / F G Am Am / F G E E | героический run-and-gun, главная тема |
| `stage2` | D Phrygian | 136 | 12 | ≈21.2 c, луп | Dm Eb Dm A / Dm Bb Gm A / Dm Bb Eb A | индустриальная крепость, тревога |
| `boss` | E minor (хроматика) | 168 | 12 | ≈17.1 c, луп | Em Em C B / Em Em C B / C D Em B | сирена, хроматический остинато |
| `victory` | C major | 140 | 6 | ≈10.3 c, один раз | C F G C F C | яркий фанфар |
| `gameover` | A minor | 100 | 4 | ≈9.6 c, один раз | Am F Dm Am | нисходящая печальная джингла |

Особенности аранжировки:

* `title` — медленный 8-ступенчатый арпеджио, лид крупными длительностями,
  том-филлы на 4/8/12 тактах, эхо 0.22.
* `stage1` — «галоп» треугольного баса, 8-е арпеджио, 16-е фразы лида,
  B-секция с подъёмом (такты 9–16), перед лупом — E-dur (G#) как доминанта.
* `stage2` — синкопированный бас, металлические открытые хэты (8.8 кГц highpass),
  тритоновая/фригийская напряжённость (Eb над Dm), арпеджио в верхнем регистре.
* `boss` — хроматические ходы лида и баса, 16-е арпеджио, тяжёлый kick
  (118→34 Гц, 0.16 c), крэш на входе в B-секцию.
* `victory` — восходящие фанфарные кварты/квинты, арпеджио на две октавы выше,
  крэш и том-филлы.
* `gameover` — редкие низкие ноты, нисходящий минорный мотив, мягкие барабаны.

Все мелодии оригинальные; цитат Contra/Konami нет. Ноты заданы именами
(`A4`, `C#5`, `Bb3`), транспонирование — через таблицу частот (A4 = 440 Гц,
равномерный строй). Генератора случайных нот в партитуре нет.

## 7. Проверка

```bash
node --check src/audio.js
node tools/audio-smoke.mjs   # печатает "OK audio smoke"
```

`tools/audio-smoke.mjs` — без зависимостей: грузит `src/audio.js` через `vm` в
фейковый `window` с mock `AudioContext` (все нужные фабрики, параметры,
`currentTime`, `state`, `resume/suspend`, `PeriodicWave`, буферы). Проверяет:

* статику файла: нет закрывающего тега скрипта, URL, `import`/`export`, сети;
* «lazy» создание `AudioContext` (до `unlock` его нет);
* вызовы до `unlock`, мусорные аргументы, отложенный трек;
* все шесть треков, переключение, повторный `startMusic`, `stopMusic`;
* все 16 SFX, mute/unmute, клампы громкости;
* `visibilitychange` (suspend/resume);
* отсутствие «убежавших» интервалов;
* отсутствие предупреждений компилятора партитуры;
* деградацию без WebAudio и fallback `webkitAudioContext`;
* ровно один добавленный глобал — `CONTRA_AUDIO`.

Дополнительно движок проверялся в реальном headless Chrome (48 кГц) через
анализатор на выходе: все треки дают сигнал (пик 0.50–0.74, RMS 0.12–0.24),
кроссфейды/мьют без провалов, граница лупа `boss` без разрыва, одноразовые
джинглы сами останавливаются (`victory` ≈11.5 c, `gameover` ≈9.6 c + хвост),
после них следующий `startMusic` работает.

## 8. Известные ограничения

* Мьют и громкость не персистятся между перезагрузками (см. §1).
* Совместимость: Chrome/Safari/Firefox, включая `file://`; при отсутствии
  WebAudio движок молча выключается (`isReady() === false`).
* `AudioContext` в мобильных браузерах создаётся/возобновляется только по жесту —
  для этого есть `unlock()` и авто-слушатели.
* Эхо-задержка зависит от темпа трека (3 шага), поэтому при смене темпа «хвост»
  предыдущего трека затухает вместе с его gain.
* Звук синтезируется в реальном времени; на очень слабых устройствах возможны
  единичные щелчки при перегрузке CPU (компрессор/лимитер защищают от клиппинга).
