# LOST VIKINGS HTML5 — контракт модулей

Браузерный ремейк **The Lost Vikings** (Interplay / Silicon & Synapse, 1992) в папке
`lost-vikings/`. Открывается двойным щелчком по `lost-vikings/index.html` (`file://`),
без сборки, CDN, интернета и внешних ассетов. Вся графика и звук генерируются кодом.

Язык интерфейса: **русский по умолчанию**, переключение на English.
Два режима графики: **8-бит (retro)** и **современный (modern)** — переключаются на лету.
Музыка: оригинальный 8-битный чиптюн на WebAudio.

Цель игры: провести **трёх викингов** — Эрика, Балеога и Олафа — через 10 уровней-головоломок
к трём выходам, используя их уникальные способности и переключаясь между ними.

## 0. Сборка и правила

```bash
node lost-vikings/tools/build.mjs      # src/*.js + src/style.css + src/template.html -> index.html
node lost-vikings/tools/probe.mjs lost-vikings/index.html lost-vikings/tmp/out.png \
     --w=1280 --h=800 --wait=900 --eval='LV_GAME.state.screen'
node lost-vikings/tools/validate-levels.mjs
```

`index.html` — **итоговый артефакт, собирает только Lead**. Исходники — в `src/`.
Порядок подключения скриптов:

1. `i18n.js`         → `window.LV_I18N`, `window.LV_T`
2. `levels.js`       → `window.LV_LEVELS`
3. `audio.js`        → `window.LV_AUDIO`
4. `game.js`         → `window.LV_GAME`
5. `render-retro.js` → `window.LV_RETRO`
6. `render-modern.js`→ `window.LV_MODERN`
7. `ui.js`           → `window.LV_UI`
8. `main.js`         → запуск, склейка

Жёсткие ограничения:

* Только **ES2019**, никаких `import/export`, `type="module"`, top-level await,
  optional chaining `?.`, `??` и прочего ES2020+. Всё работает по `file://`.
* Каждый файл — IIFE, пишет в глобал **только свой** неймспейс, `'use strict'` внутри.
* Никаких внешних файлов, шрифтов, BASE64-картинок и сетевых запросов.
* Не редактировать чужие файлы. Не собирать `index.html` (это делает Lead).
* Не коммитить. Временные файлы — в `tmp/<имя-агента>/` (не входит в артефакт).

## 1. Мир, сетка, физика (общая база для игры и валидатора)

* Размер уровня: **24 × 15 клеток**, клетка **16 px**. Мир = **384 × 240 px**, весь уровень
  виден сразу, камеры нет. Клетка `(tx,ty)` занимает `x ∈ [tx·16, tx·16+16)`,
  `y ∈ [ty·16, ty·16+16)`.
* Актор: коробка **10 × 22 px**, `actor.x` — центр по горизонтали, `actor.y` — **низ (ноги)**.
  Левый/правый край: `x ∓ 5`, верх: `y − 22`.
* Гравитация `1400 px/с²`, терминальная скорость `520 px/с`, coyote-time `0.08 с`,
  jump-buffer `0.12 с`.
* Скорости и прыжки:

| Викинг | Скорость | Начальная скорость прыжка | Высота прыжка | Берёт уступ |
|---|---|---|---|---|
| Erik | 130 px/с | 400 px/с | ≈ 57 px (3.5 клетки) | 3 клетки |
| Baleog | 95 px/с | 330 px/с | ≈ 39 px (2.4 клетки) | 2 клетки |
| Olaf | 75 px/с | 260 px/с | ≈ 24 px (1.5 клетки) | 1 клетка |

* Твёрдые тайлы: `#`, `B` (ломаемый), закрытые ворота `a–d`.
* `=` — односторонняя платформа: сверху на неё встают, снизу пролетают, спрыгнуть вниз можно
  (`↓` + `прыжок`).
* `^` — шипы: касание = смерть викинга.
* Викинги не сталкиваются друг с другом. Неактивные викинги стоят на месте.
* Падение за нижнюю границу = смерть. Уровень всегда огорожен `#`.

## 2. Механика и способности

### 2.1 Управление одним викингом

Активен всегда ровно один викинг. Остальные неподвижны, но физика (платформы, плиты)
продолжает учитывать их позиции.

| Действие | Клавиши |
|---|---|
| Идти | `←` `→`, `A` `D` |
| Прыжок | `Space`, `W`, `↑` |
| Действие (уникальное) | `J`, `K`, `Enter`, `F` |
| Сменить викинга | `1` `2` `3`, `Tab`, `Q` `E` |
| Пауза | `P`, `Esc` |
| Рестарт уровня | `R` |
| Графика | `G` |
| Язык | `L` |
| Звук | `M` |

### 2.2 Erik the Swift (Эрик Быстрый) — цвет оранжево-красный

* Быстрее всех, прыгает выше всех.
* **Действие — таран**: если в клетке на уровне груди **или головы** перед ним тайл `B`,
  после 0.18 с замаха один кирпич разрушается (стопка из двух ломается за два удара),
  Эрик получает лёгкий отскок. Кулдаун 0.5 с. Только Эрик может ломать `B`.
* Остальные `#` не ломаются.

### 2.3 Baleog the Fierce (Балеог Свирепый) — цвет зелёный

* **Действие — выстрел из лука**: стрела летит горизонтально в сторону взгляда
  со скоростью 300 px/с, исчезает о твёрдый тайл/границу. Попадание:
  * убивает врага `M`;
  * **переключает рычаг** `5–8` (открывает/закрывает ворота своей группы);
  * ничего не делает с `#`/`B`/воротами.
* Если враг вплотную (≤ 22 px) — дополнительно срабатывает удар мечом (тот же эффект,
  визуально меч). Стрелы бесконечны, кулдаун 0.35 с.
* Прыгает на 2 клетки, быстрее Олафа.

### 2.4 Olaf the Stout (Олаф Толстый) — цвет сине-голубой

* Медленный, прыгает на 1 клетку.
* **Действие — поднять щит** (удержание): Олаф встаёт (state `brace`), над головой
  появляется горизонтальная **платформа щита**: верх на `y − 30`, ширина 20 px (`x ± 10`).
  Другие викинги могут стоять на щите, прыгать с него и использовать как ступень.
  Олаф не может идти, пока щит поднят (можно отпустить в любой момент).
* Щит **блокирует вражеские стрелы** из ловушек `<` `>`: стрела, попавшая в зону
  `x ± 12`, `y − 30 … y − 8`, исчезает; Олаф не гибнет. Без щита — гибнет, как все.
* Контакт с врагом `M` убивает любого викинга (и Олафа со щитом).

### 2.5 Тайлы уровня

| Символ | Значение |
|---|---|
| `.` | пусто |
| `#` | камень (твёрдый, неразрушимый) |
| `B` | ломаемый кирпич (только Эрик тараном) |
| `=` | односторонняя платформа (прыжок снизу) |
| `^` | шипы (смерть) |
| `a` `b` `c` `d` | ворота группы A/B/C/D; закрыты, пока группа не открыта (твёрдые) |
| `1` `2` `3` `4` | нажимная плита: пока на ней стоит любой живой викинг — ворота `a/b/c/d` открыты |
| `5` `6` `7` `8` | рычаг: выстрел Балеога переключает ворота `a/b/c/d` (5→a, 6→b, 7→c, 8→d) |
| `<` | ловушка-стреломёт, стреляет влево каждые 2.2 с (вражеская стрела) |
| `>` | ловушка-стреломёт, стреляет вправо каждые 2.2 с |
| `M` | пещерный враг: патрулирует платформу, контакт смертелен; убивается Балеогом |
| `*` | сокровище (+100 очков, необязательное) |
| `E` `&` `O` | старты Эрика, Балеога, Олафа (ровно по одному; `B` — это кирпич!) |
| `X` | выход (ровно 3): у каждого викинга СВОЯ дверь (поле `exitFor`), чужая не открывается; коснувшийся своей двери уходит с уровня |

Старты не могут стоять в твёрдом тайле/шипах; под ними должна быть опора. Плиты `1–4` тоже стоят на опоре (клетка под плитой твёрдая), иначе нажать нельзя.
Выходы стоят на опоре.

### 2.6 Правила завершения и смерти

* Викинг коснулся выхода `X` → он `gone` (исчезает), выход помечается занятым.
  Одним выходом можно спасти только одного викинга.
* Все трое ушли → уровень пройден.
* Любая смерть викинга (шипы, враг, вражеская стрела, падение) → **рестарт уровня**
  через 1.3 с, счётчик смертей +1, собранные сокровища уровня сбрасываются.
* Сокровища дают очки, время и смерти — статистика уровня.

## 3. `src/levels.js` — уровни (владелец: level-architect)

```js
window.LV_LEVELS = [
  {
    id: 1,
    theme: "cave",                    // cave | forge | ice | forest | castle | void
    name: { ru: "Пробуждение", en: "Awakening" },
    hint: { ru: "…", en: "…" },       // до 100 символов, подсказка без спойлеров
    exitFor: ["erik", "baleog", "olaf"], // порядок = порядок X по строкам сверху вниз, слева направо
    rows: [ /* ровно 15 строк, каждая ровно 24 символа */ ]
  },
  // … ровно 10 уровней
];
```

Требования (валидируются `tools/validate-levels.mjs`):

1. Ровно **10** уровней, id 1–10, все `name`/`hint` на RU и EN, темы по вкусу
   (рекомендация: 1 cave, 2 cave, 3 forge, 4 forge, 5 ice, 6 ice, 7 forest, 8 castle,
   9 castle, 10 void — можно иначе).
2. `rows.length === 15`, `rows[y].length === 24`, только символы из таблицы.
3. Периметр — `#` (допускаются только `#`).
4. Ровно один `E`, один `&`, один `O`; ровно три `X`. (`B` — ломаемый кирпич, не старт!)
5. Старты и выходы: клетка не твёрдая, не шипы, не ловушка, под ней опора
   (`#`, `B`, `=`, закрытые ворота). На старте клетка не `X`/`*`.
6. **Щедрая достижимость**: при открытых воротах, убранных `B`, игнорируя врагов и ловушки,
   каждый викинг должен достичь **своей** двери (`exitFor`), а каждый `*` — достижим
   хотя бы одним викингом. Модель BFS: шаг по горизонтали, подъём по лестнице прыжка
   (2.2.1: Erik +3 клетки, Baleog +2, Olaf +1), падение вниз, платформы `=`.
7. Хотя бы один уровень должен требовать каждую способность (таран `B`, рычаг `5–8`,
   щит Олафа как ступень, ловушку перекрыть щитом, плиту придержать неактивным викингом).
   Это подтверждается прохождением в `docs/LEVELS.md`.
8. Сложность растёт; уровни не пустые: используйте вертикаль, развилки, сокровища.

### `docs/LEVELS.md` — обязательное прохождение

Для каждого уровня — короткий разбор (5–12 строк): как провести всех троих,
какие способности задействованы, где сокровища. Это доказательство проходимости
и текст для QA. Без него задача не принимается.

### `tools/validate-levels.mjs`

Node.js без зависимостей: читает `src/levels.js` через `vm`, проверяет пункты 1–6,
печатает таблицу (id, тема, сокровища, ворота/плиты/рычаги, враги, достижимость)
и в конце `OK — 10/10`. Код возврата 0/1.

## 4. `src/audio.js` — музыка и звук (владелец: audio-smith)

`window.LV_AUDIO`, только WebAudio, без внешних файлов. Всё синтезируется.

```js
LV_AUDIO.unlock();             // создать/resume AudioContext (первый жест)
LV_AUDIO.startMusic(mode);     // 'title' | 'game'; зациклено, идемпотентно
LV_AUDIO.stopMusic();          // плавно, без щелчков
LV_AUDIO.setGameTrack(0|1);    // два разных игровых трека (чередуются по уровням)
LV_AUDIO.sfx(name);            // см. список
LV_AUDIO.jingle(name);         // 'win' | 'death' | 'level' | 'finale' — короткий, не ломает музыку
LV_AUDIO.setPaused(bool);      // пауза музыки (без kill контекста)
LV_AUDIO.setMuted(bool); LV_AUDIO.toggleMuted(); LV_AUDIO.getMuted();
LV_AUDIO.setVolume(0..1); LV_AUDIO.isReady();
```

SFX: `jump`, `land`, `headbutt`, `break`, `arrow`, `sword`, `lever`, `gate`, `plate`,
`treasure`, `exit`, `switch`, `click`, `hurt`, `death`, `trap`.

Требования:

* Вызовы безопасны до `unlock()`, при повторных вызовах, без AudioContext — без исключений.
* Планировщик нот с lookahead ≥ 100 мс, очистка при stop, остановка осцилляторов.
* Громкость музыки ниже SFX, без клиппинга, мягкий fade in/out, master-громкость.
* Композиции **оригинальные** (не копировать мелодии Lost Vikings и других игр):
  * `title` — загадочный северный чиптюн (медленный, 90–100 BPM, минор, арпеджио);
  * `game` — два энергичных лупа 130–145 BPM: пуншевый треугольный бас, две пульсовые
    дорожки (лид + арпеджио), шумовые барабаны; треки заметно разные (разные тональности/грув);
  * `jingle` — короткие (1.5–3 с) победный/смертельный/финальный мотивы.
* Поддержка Chrome/Safari/Firefox: `AudioContext` + `webkitAudioContext`.
* `node --check src/audio.js` проходит. Дополнительно — офлайн-тест планировщика
  с заглушкой AudioContext в `tmp/audio-smith/` (по желанию, но приветствуется).

## 5. Рендереры: `src/render-retro.js` и `src/render-modern.js`

Оба файла получают одинаковый **view** и рисуют весь мир. Никакой логики игры в рендерерах.

```js
window.LV_RETRO = {
  init(canvas),              // единожды: canvas 384×240 (retro) / 1152×720 (modern)
  draw(view),                // вызывается каждый rAF, пока идёт экран игры
  drawPortrait(canvas, id, t), // портрет викинга 'erik'|'baleog'|'olaf' в HUD (сам задаёт размеры)
  drawTitle(canvas, t)       // анимированный фон титульного экрана (сам задаёт размеры)
};
```

`LV_MODERN` — тот же интерфейс. Размеры канваса:

| | retro | modern |
|---|---|---|
| игровой канвас | 384×240, `image-rendering: pixelated` | 1152×720, масштаб 3× |
| портрет | 48×56 | 192×224 |
| титульный фон | 384×240 | 1152×720 |

Modern рисует в мировых координатах 384×240, предварительно
`ctx.setTransform(3,0,0,3,0,0)` (или эквивалент), чтобы view был один и тот же.
Retro — настоящий низкий буфер 384×240; CSS растягивает его целым числом пикселей.

### 5.1 View (снимок состояния; поля стабильны)

```js
view = {
  t: 12.34,                       // секунды игрового времени (для анимаций)
  theme: "cave",                  // cave|forge|ice|forest|castle|void
  w: 24, h: 15,
  terrain: [ /* 15 СТРОК по 24 символа: '.', '#', 'B', '=', '^' */ ],
  gates:    [{ x, y, group: "a", open: 0..1, anim }],
  plates:   [{ x, y, group: "a", pressed: true }],
  levers:   [{ x, y, group: "a", on: true }],
  traps:    [{ x, y, dir: -1 | 1 }],
  treasures:[{ x, y, taken: false }],
  exits:    [{ x, y, filledBy: null | "erik", who: "erik"|"baleog"|"olaf", anim }],
  actors:   [{ id: "erik", x, y, dir: 1, vx, vy, onGround: true,
               state: "idle|run|jump|fall|act|brace|dead|gone",
               active: true, shield: false, anim: 3.2 }],
  enemies:  [{ x, y, dir: -1, state: "walk|die", alive: true, anim: 1.1 }],
  arrows:   [{ x, y, dir: 1, hostile: false }],   // лучшие координаты — центр стрелы
  fx:       [{ type: "dust|spark|break|pickup|hit|death|level", x, y, age, ttl, dir }],
  shake: 0..1, flash: 0..1, active: "erik"
};
```

* `x`,`y` — мировые пиксели; `y` у акторов — ноги. Клетки — `x*16`.
* Рендерер не мутирует view.
* Ворота рисуются как твёрдая решётка при `open < 0.5`, анимация подъёма/ухода.
* Занятый выход (`filledBy != null`) — подсвечен/заполнен.
* Состояние `brace` у Олафа — щит поднят; `shield` дублирует флаг.
* `fx` — частицы, рисуются и исчезают по `age/ttl`.

### 5.2 Retro (8-бит): стиль

* Аутентичный пиксель-арт: тайлы 16×16, викинги ~10×22 px, враги 10×20.
* Палитра NES/Amiga-подобная, 3–4 цвета на тайл, ограниченная общая палитра на тему.
* Узнаваемые силуэты: Эрик — рыжий, рогатый шлем, быстрый; Балеог — зелёная туника,
  меч и лук; Олаф — крупный, синий, круглый щит.
* Тайлы: камень с крапом, кирпич с трещинами, платформы, шипы, ворота-решётка,
  плита, рычаг, ловушка-арбалет, сундук/самоцвет, выход-дверь с руной.
* Анимации: idle (2 кадра), бег (4), прыжок, падение, таран, выстрел, смерть, щит.
  Достаточно 2–3 кадра на состояние, смена по `anim`.
* Фон темы: параллакс-паттерн (сетка пещеры, кирпичи кузни, кристаллы льда, лес, замок, звёзды).
* Опционально: лёгкая виньетка/скан-линии — но их может дать CSS; canvas не обязан.

### 5.3 Modern: стиль

* Тот же мир, но «стильно модно»: тёмный фон с аврора-градиентом/туманом, мягкие
  свечения (shadowBlur), стеклянные тайлы с тонкими контурами, частицы, плавные силуэты.
* Викинги — выразительные векторные фигуры с простой процедурной анимацией (ноги/руки,
  плащ/шлем), свечение-подсветка активного героя, контурная обводка.
* Сокровища — светящиеся кристаллы с импактом; выходы — порталы с кольцами; враги —
  тёмные твари с глазами; ловушки — механические турели.
* Terra-фон темы: глубокий градиент + параллакс-слои + виньетка + зерно (по желанию).
* Активный викинг подсвечен, неактивные — приглушены. Занятый выход — насыщенный цвет.
* Производительность: 60 fps, без честного motion blur; canvas 2D.

### 5.4 Обязательная самопроверка художника

## 6. `src/game.js` — ядро (владелец: Lead)

`window.LV_GAME`:

```js
LV_GAME.init({ levels, audio, onEvent });  // подготовка
LV_GAME.startLevel(index);                 // 0..9
LV_GAME.update(dt);                        // dt в секундах, клампится
LV_GAME.render(view?)                      // собирает view
LV_GAME.getView();
LV_GAME.input(action, down);               // 'left','right','jump','action','switch1..3'
LV_GAME.switchTo(id); LV_GAME.restartLevel();
LV_GAME.pause(bool); LV_GAME.isPaused();
LV_GAME.state                               // { screen:'playing'|'complete'|'dead', levelIndex, ... }
LV_GAME.debug                               // телепорт/отладка для QA
```

`onEvent(name, data)` — Lead передаёт в UI: `death`, `complete`, `treasure`, `switch`, `jump`…
UI сам решает, что показывать, звук вызывается из game.js через `audio`.

## 7. Стиль UI (Lead)

Тёмный «северный неон»: стеклянные панели, аврора-градиенты, крупная сжатая типографика,
руны/скандинавские мотивы, аккуратные микроанимации. В retro-режиме интерфейс
переключается на пиксельный скин (monospace, острые рамки, скан-линии), в modern —
на глянцевый. Русский по умолчанию, EN по `L`.

## 8. Порядок работы

1. Lead кладёт каркас, контракт, `build.mjs`, `probe.mjs`.

4. Интеграция: Lead прогоняет игру, шлёт агентам замечания, те чинят свои файлы.
5. QA-агент проверяет проходимость 10 уровней, оба рендерера, i18n, звук, мобильный вид.
6. Lead финализирует README, скриншоты, `index.html`.
