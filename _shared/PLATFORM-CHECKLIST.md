## 7. Режим 16:9 (Poki, CrazyGames)

`node tools/platform-build.mjs <slug> gamepush <out> --aspect 16:9` → `<slug>-gamepush-16x9/`: `js/aspect.js` (копия `_shared/aspect.js`)
вписывает игру в сцену 16:9 по высоте без искажений, поля — фоном в тон темы игры (узор меняется с темой T), кнопки `position:fixed` — внутрь
сцены, подвал скрыт; в окне не 16:9 — чёрные поля вне сцены; в портретном окне (телефон стоя) сцена = всё окно. Проверено тестом на 1280×720,
1920×1080, 1024×768 (+ телефон/планшет) для всех трёх игр: canvas внутри сцены, пропорции сохранены, прокрутки нет. ⚠ У Poki ручной отбор
и (по ряду источников) эксклюзив — бэкенда Poki SDK в адаптере нет.

## 8. Процесс подачи (Яндекс, concepts/moderation и история изменений) — до первой заявки

| Правило | Что делаем |
|---|---|
| **Новый аккаунт без истории — 1 заявка** на новую игру одновременно, обычный — 2 («Единовременно можно отправить не больше двух заявок…, а с аккаунта без истории — одну»). Обновления опубликованных игр — без лимита | пилот подаём **по одной**: ОТБОЙНИК → КЛАДКА → КАСКАД (риск 3.6 — последним) |
| **Кулдаун после отказа удваивается**: 24 ч → 2 → 4 → 8 → 16 дней (максимум 384 ч); кнопка «Сброс кулдауна модерации» — не чаще раза в 28 дней | перед подачей — прогон этого чек-листа и `platform-builds.browser.mjs`; сброс — только при срочности |
| Отозвать черновик — в течение 2 ч после отправки | ошибку заметили сразу — отзываем, а не ждём отказа |
| Одна модерация на игру одновременно: черновик, A/B креативов или A/B версий | A/B иконок не запускать, пока на модерации обновление той же игры |
| Проверка многоэтапная, список замечаний может быть неполным | закладывать 1–2 итерации на первую игру |
| **Договор (ЕЛС или РСЯ) — обязательное условие для открытия модерации** (история изменений, 31.08.2026) | 🔒 владелец: статус договора «Активен» до первой подачи |
| Покупки: запрос на подключение — **до публикации**, «чем раньше — тем лучше» (14.04.2026); проверка необработанных покупок — «даже во время тестов» | 🔒 владелец (если продаём «Без рекламы»); код готов (1.13.1) |
| Игра была на проверке > 100 дней назад — предупреждение, что требования могли измениться | раз в квартал — регресс опубликованных игр по этому чек-листу |
| Поле «Горизонтальное видео» обязательно; название уникально в каталоге | ✅ MP4 16:9 есть; 🔒 уникальность — 5.12 |
| ПРИИСК, ПОРУБЕЖЬЕ, МАЯЧНИЦА (kvest) — «демо»-издания | под площадку **не собираются** (автопроверка 1.15). Для будущей сборки: в сборке под площадку — издание без слова «демо»: заголовок/описание (`<title>`, `meta description`), строки `demoTag`, «Скирмиш в демо…», экран «Продолжение — в полной версии» и значение издания `'demo'` в коде заменить на полную игру с разблокировкой покупкой (IAP) или законченную первую кампанию; без отсылок к «полной версии» на другой площадке и к Steam (8.4); `promo/<slug>/promo.json` — без «Демо» в подзаголовках каталога |

## Что осталось проверить только с аккаунтом / вручную
1. Консоль Яндекса: debug-панель (`&debug-mode=16`): индикатор «I18N is used», переключение RU/EN; события ready/start/stop; реклама в тестовом режиме.
2. Черновик Яндекса: включить облачные сохранения (1.11); проверить уникальность названий (5.12); выбрать категории по механике (2.3); ориентация — портрет (4.3); стики-баннер — место и перекрытие кнопок; договор ЕЛС «Активен».
3. GamePush: проекты и ключи → конфиг вне репо → пересобрать; поле игрока `arcade_save` (data); согласовать отсутствие покупок; проверить точный адрес загрузчика SDK.
4. Реальные устройства: бюджетный Android (Chrome, Яндекс Браузер), iPhone (Safari: долгий тап, звук после рекламы), десктоп Firefox/Safari.
5. Пары похожих игр в каталоге (3.6), особенно для КАСКАДА.
6. Финальное «ок» владельца на публикацию каждой игры.
